# Ревизии схемы

Здесь лежат миграции. Файлы создаются командой, а не руками:

```
alembic revision --autogenerate -m "что меняем"
```

**Автогенерацию обязательно читать глазами.** Alembic видит не всё:
переименование колонки он покажет как «удалить одну, создать другую» —
то есть как потерю данных. В таких случаях сгенерированный файл
правится вручную на `op.alter_column(..., new_column_name=...)`.

## Первая ревизия ещё не создана

Схему на боевой базе создал `models.py --create` до того, как появился
alembic. Чтобы история началась с текущего состояния:

```
alembic revision --autogenerate -m "baseline"   # опишет то, что уже есть
alembic stamp head                              # отметить базу как накатанную
```

`stamp` ничего не выполняет — он только записывает в таблицу
`alembic_version`, что эта ревизия уже применена. Без него первый же
`upgrade` попытается создать таблицы, которые есть, и упадёт.

На пустой базе (новый сервер, тестовый стенд) всё иначе — там просто:

```
alembic upgrade head
```

## После этого

`models.py --create` остаётся только для самого первого разворачивания
роли и базы. Таблицы дальше создаёт и меняет alembic: два способа
менять схему — это два расходящихся представления о ней.
