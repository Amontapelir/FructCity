# Бэкенд

FastAPI + PostgreSQL. Это весь сервер магазина: витрина, админка,
публичное API, SSR-страницы и раздача статики.

```
app/domain/    чистые функции: расчёты, правила, представления (только stdlib)
app/db/        схема, чтение, запись, перенос и переключение
app/api/       HTTP: контекст запроса и роутеры
alembic/       ревизии схемы
tests/         188+ тестов, штатный unittest
```

## Запуск и проверка

```
uvicorn backend.app.main:app --port 8000       # из корня проекта
python -m unittest discover -s backend/tests -t .
```

Состояние сервера — `GET /healthz`: откуда читаются данные, разрешена ли
запись, сколько товаров в каталоге.

## Правило слоёв

Вниз можно, вверх нельзя. Домен не знает ни о FastAPI, ни о базе:
принимает состояние аргументом, возвращает структуру. Благодаря этому
большая часть проверок гоняется обычным вызовом функции — без поднятого
приложения, без базы и без сети.

Роутер — тонкая обёртка: разобрал запрос, проверил право, позвал домен
внутри транзакции. Появилась логика в роутере — её место в `domain/`.

## Где искать ответы

Причины решений живут рядом с кодом: каждый модуль начинается с
docstring, который отвечает на три вопроса — что это, почему сделано
так и чего здесь делать нельзя. Начинать стоит с него, а не с чтения
самих функций.

Что где лежит:

| Вопрос | Файл |
|---|---|
| Как считаются деньги, скидки, доставка, слоты | `app/domain/calc.py` |
| Правила заказа: корзина, отмена, пересчёт | `app/domain/shop.py` |
| Таблицы и связи | `app/db/models.py` |
| Как состояние читается и пишется | `app/db/repository.py`, `app/db/uow.py` |
| Что проверяется и чем | `tests/` |
| Ветки, коммиты, вливание | `../CONTRIBUTING.md` |
