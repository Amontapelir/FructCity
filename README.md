# FructCity — как запустить

Интернет-магазин продуктов: витрина, админ-панель и API.
Бэкенд на Python (FastAPI), данные — в PostgreSQL.

---

## Быстрый старт

**1. Нужны Python 3.12+ и PostgreSQL 15+.** Python — с
[python.org](https://www.python.org/downloads/) (при установке отметьте
«Add Python to PATH»), PostgreSQL — с
[postgresql.org](https://www.postgresql.org/download/).

**2. Установите зависимости** — один раз, в папке магазина:

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend/requirements.txt     REM Windows
.venv/bin/python -m pip install -r backend/requirements.txt             # macOS, Linux
```

**3. Пропишите доступ к базе** в файле `.env` рядом с магазином:

```
FC_DB_NAME=fructcity
FC_DB_USER=fructcity
FC_DB_PASSWORD=пароль
FC_DB_HOST=127.0.0.1
FC_WRITE_ENABLED=1
```

**4. Создайте базу и таблицы:**

```
python -m backend.app.db.models --create
```

Команда заводит роль приложения и саму базу, делая роль её владельцем.
Базу, созданную вручную под `postgres`, приложение наполнить не сможет:
с PostgreSQL 15 схема `public` принадлежит владельцу базы.

**5. Запустите магазин:**

| Система | Что сделать |
|---|---|
| Windows | Двойной клик по **`start.cmd`** |
| macOS, Linux | В терминале: `./start.sh` (один раз до этого: `chmod +x start.sh`) |

Закрыть — Ctrl+C или закрыть окно консоли.

## Адреса

| Что | Адрес |
|---|---|
| Витрина | http://127.0.0.1:8000 |
| Каталог | http://127.0.0.1:8000/catalog |
| Админ-панель | http://127.0.0.1:8000/admin |
| Состояние сервера | http://127.0.0.1:8000/healthz |

`/healthz` отвечает JSON: откуда читаются данные (`source`), разрешена ли
запись (`write_enabled`) и сколько товаров в каталоге. Это первое место,
куда стоит заглянуть, если витрина ведёт себя странно.

**Логины персонала:** `admin` (полный доступ) и `manager` (только заказы
и предзаказы). Пароли задаются при заведении сотрудника и меняются в
админке, раздел «Сотрудники».

## Что попробовать

**Как покупатель.** Положите товар в корзину, оформите заказ. Возьмите
что-нибудь весовое — например, огурцы: увидите, как считается примерный вес
и предупреждение о допуске ±10%. Промокоды для проверки: `FRUCT10` (−10% на
неакционное, от 1000 ₽), `MINUS200` (−200 ₽ от 1500 ₽), `FREEDEL`
(бесплатная доставка).

**Вход в личный кабинет** — по коду из SMS. Провайдер не подключён, поэтому
код показывается прямо на экране: так задумано на время разработки,
отключается строкой `FC_DEV_OTP` в `.env`.

**Как сотрудник.** Зайдите в админку, откройте заказ. Для весовой позиции
впишите фактический вес — сумма пересчитается, а при отклонении больше 10%
появится требование связаться с клиентом. Кнопка «Лист сборки» открывает
печатную форму. Раздел «Главная страница» — конструктор витрины: блоки
двигаются и отключаются, изменения видны сразу.

Чтобы почувствовать разницу ролей, войдите под `manager` — лишние разделы
исчезнут. Они закрыты и на сервере, не только спрятаны в меню.

## Настройки

Всё меняется в файле `.env` рядом с магазином. После правки перезапустите.

| Строка | Зачем |
|---|---|
| `FC_DB_*` | Доступ к базе: имя, пользователь, пароль, хост |
| `FC_WRITE_ENABLED=1` | Разрешить запись в базу. Без неё магазин только читает |
| `NODE_ENV=development` | `production` для боевого режима (см. ниже) |
| `FC_DEV_OTP=1` | Показывать код из SMS на экране. В продакшене убрать |
| `FC_TELEGRAM_BOT=`, `FC_TELEGRAM_SECRET=` | Привязка Telegram |

Порт задаётся при запуске: `uvicorn backend.app.main:app --port 8080`.

## Если что-то не так

**«python не является внутренней или внешней командой»** — Python не
установлен либо установлен без добавления в PATH. Переустановите,
отметив «Add Python to PATH», и откройте консоль заново.

**Порт занят** — запустите с другим портом:
`uvicorn backend.app.main:app --port 8080`.

**«База недоступна, работаю на JSON» в консоли** — приложение не
достучалось до PostgreSQL. Проверьте `FC_DB_*` в `.env` и что сервер
базы запущен; подсказка о причине печатается там же.

**`/healthz` показывает `write_enabled: false`** — в `.env` нет
`FC_WRITE_ENABLED=1`. Без него магазин работает в режиме чтения: каталог
виден, а заказ оформить нельзя (`write_disabled`).

**Окно мигнуло и закрылось** — запустите `start.cmd` из уже открытой
консоли, чтобы увидеть текст ошибки: откройте папку, наберите в адресной
строке проводника `cmd` и нажмите Enter, затем введите `start.cmd`.

**Куча строк вида `'xx' is not recognized as an internal or external
command`** — в `start.cmd` попал русский текст. Так делать нельзя:
`cmd.exe` читает bat-файл в кодировке OEM (866 на русской Windows), и
кириллица разваливается на обрывки, которые он пытается выполнить как
команды. `chcp 65001` не помогает — файл уже прочитан к этому моменту.
Поэтому `start.cmd` намеренно содержит только латиницу. Если правите
запуск — держите `.cmd` в ASCII.

**Забыли пароль от админки** — заведите или измените сотрудника в
админке под другой учётной записью администратора. Если администраторов
не осталось, пароль меняется прямой правкой строки в таблице `users`:
хеш считается тем же форматом, что и в `backend/app/domain/security.py`.

**`401` на `/api/admin/me` в консоли браузера** — это не ошибка. Так страница
проверяет, вошли ли вы; при отрицательном ответе показывается форма входа.

**Картинки товаров не грузятся** — фотографии подтягиваются с Wikimedia
Commons, нужен интернет. Без него подставляются эмодзи, всё остальное
работает.

## Развёртывание через Docker

Альтернатива «Быстрому старту» выше — весь стек (приложение + PostgreSQL)
поднимается одной командой, без ручной установки Python и базы.

```bash
cp .env.example .env
# заполните FC_DB_PASSWORD, FC_DB_ADMIN_PASSWORD, FC_ADMIN_PASSWORD,
# FC_MANAGER_PASSWORD — и обязательно FC_WRITE_ENABLED=1, иначе магазин
# поднимется в режиме «только чтение» (см. .env.example)

docker compose up --build -d
```

Приложение слушает `http://127.0.0.1:8000` (порт меняется переменной
`PORT` в `.env`). При первом запуске контейнер `app` сам ждёт готовности
Postgres и создаёт схему (`python -m backend.app.db.models --create`,
идемпотентно — на каждом следующем перезапуске просто ничего не делает
заново).

**`/healthz` отвечает 503 сразу после первого запуска — это ожидаемо.**
Пустая база — это не пустой магазин, а незавершённый перенос данных
(`db/source.py`), поэтому витрина сознательно не открывается, пока в
каталоге нет ни одного товара. Добавьте товары через `/admin` (или
перенесите существующий `store.json`, если он есть — см.
`python -m backend.app.db.migrate_json`), после чего перезапустите
контейнер приложения, чтобы он заново выбрал источник данных:

```bash
docker compose restart app
curl http://127.0.0.1:8000/healthz
# {"ok":true,"source":"postgres","products":N,...}
```

Данные Postgres живут в именованном томе `pgdata` и переживают
`docker compose down` (без `-v`). `docker compose down -v` стирает и том —
для чистого повторного разворачивания, а не для обычной остановки.

Этот `docker-compose.yml` — для одной машины. Обратный прокси и HTTPS
(следующий раздел) он не заменяет.

## Перед боевым запуском

Сейчас это рабочий прототип, запускаемый локально. Для публикации в
интернете обязательно:

1. **HTTPS.** Поставьте `NODE_ENV=production` — cookie станут `Secure`.
   Сам сертификат выдаёт обратный прокси (nginx, Caddy). Он же берёт на
   себя сжатие ответов.
2. **Уберите `FC_DEV_OTP`** — иначе код входа виден в ответе сервера, и
   войти в чужой аккаунт можно, зная только номер телефона.
3. **Смените пароли** персонала на собственные.
4. **Настройте бэкап базы PostgreSQL** — это всё содержимое магазина.
   Файл `data/store.json` больше не обновляется: он остался снимком на
   момент переезда и годится только для отката.
5. **Подключите провайдеров:** SMS для кодов входа, платёжный шлюз,
   Telegram-бот. Серверная часть под них готова, нужны ключи.

Как устроен сервер и где что искать — `backend/README.md`. Правила
работы с репозиторием — `CONTRIBUTING.md`.
